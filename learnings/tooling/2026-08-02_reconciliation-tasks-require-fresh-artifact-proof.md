# Reconciliation tasks require fresh artifact proof

When a completed implementation exists only as dirty working-tree edits, prior passing tests do not prove that a deployable artifact contains the fix. Treat reconciliation as a provenance exercise:

1. Restrict the diff to task-owned paths and map each hunk to the original RED, implementation, or acceptance evidence.
2. Preserve unrelated dirty files instead of cleaning the tree or absorbing them into the artifact.
3. Re-run focused behavior tests and type/build gates from the current source state.
4. Inspect the freshly generated module for the exact ownership and data-flow invariants, and reject stale symbols from the broken path.

For bundled channel runtime fixes, source proof and generated proof should agree. In the Discord deliberation case, the generated message-handler module must import the narrow reply dispatcher, include the sender-id fallback, and omit the old lazy broad-runtime loader. Existing `dist/` content is only context until regenerated by the current run.
