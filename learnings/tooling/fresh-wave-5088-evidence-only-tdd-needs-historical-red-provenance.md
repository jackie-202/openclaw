An evidence-only follow-up needed to document an already completed implementation. The TDD capture helper rejected the proof because its RED section referenced a genuine failure from the parent task rather than a RED run generated by the helper itself. Re-running a failing test solely to satisfy the helper would have fabricated evidence. Preserve historical RED output with an explicit parent-task reference, then execute the focused test command normally and append fresh GREEN output with its command and exit code. Evidence tooling should support separate modes for newly captured RED runs and verified historical RED provenance.
