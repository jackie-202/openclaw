# Audit: OpenClaw deliberation pipeline routing and delivery safety

## Verdict

**NOT SAFE** for proposal `proposal-20260820-203458-161e2c` rollout.

The checked-out OpenClaw implementation has a sound nominal pipeline-selection and immutable-target path, but it does not meet the proposal's separate-intake, source-silence, no-fallback, at-most-one-provider-attempt, receipt, bounded-migration, or fixture-consistency requirements. These are independent rollout blockers, not external-convergence unknowns.

## Scope

- Audited repository: current `openclaw-fork` checkout only.
- Base commit: `90eeb86db1e74fc6048a641a5095cdd4b665d72c`.
- Worktree: dirty; the modified and untracked Deliberation source, tests, contracts, proposal, and docs are the implementation under audit.
- Audit time: `2026-08-21T15:26:10Z`.
- Excluded as required: `km-system`, live OpenClaw configuration, runtime secrets, and external systems.
- External KM deployment, live config migration, Slack allowlist, and owner-repository convergence remain **UNKNOWN**.

## Remediation Before Rollout

1. **Enforce one real platform attempt.** Add a Deliberation-safe outbound mode/capability that performs exactly one text API attempt, disables Discord webhook fallback and transport retries, disables Slack DNS retries/rechunking, carries the durable idempotency key when the provider supports it, and returns an exact one-message receipt. Add real Deliberation-to-native-adapter composition tests for accepted-then-error and partial-send cases.
2. **Restore source ownership before channel transformations.** Preserve authenticated Discord parent/source facts through `autoThread`, or claim/suppress configured Deliberation traffic before auto-thread retargeting. Move fail-closed source suppression before fast abort and add failure/disabled/empty/room-event/auto-thread tests proving zero ordinary replies and zero model dispatch.
3. **Guarantee one intake per provider event.** Exempt configured Deliberation sources from Discord/Slack inbound debounce aggregation and prove two same-window provider event IDs produce two intake calls. Reconcile or remove the KM 60-second multi-message burst contract so one inbound cannot merge into another deliberation item.
4. **Make Discord history thread-exact.** Carry authenticated Discord child-thread identity into the history request/store boundary and read that thread, while retaining the parent channel as source-route authority. Add Discord root/child history tests parallel to the Slack vectors.
5. **Repair completion semantics.** Treat accepted-then-error transport/timeout outcomes as unresolved, reject Discord `unknown` receipts, reject duplicate attempt IDs, and represent exactly one platform message in completion evidence. Align the runtime record parser with all schema-permitted projection fields or narrow the schema.
6. **Regenerate and validate wire fixtures.** Add `pipelineId` and exact target `mode`/`threadId` evidence to all lifecycle cases, keep each negative case otherwise valid, and add a test that validates every request and status-specific response against the referenced closed schema. Reissue provenance only after local semantic consistency is green; continue marking external KM adoption unknown until independently proven.
7. **Bound legacy compatibility.** Define a tagged-release cutoff and plugin-owned doctor migration/writeback, then remove runtime legacy acceptance after the shipped migration window. A comment tied to live-config state is not a repository-verifiable bound.
8. **Repair integration proof.** Update `km-listener.cross-repo.ts` to the current producer input, rerun the same contract RED command as GREEN, and capture current exact commands/results. Do not treat repository-local hashes as proof of live or external owner convergence.

Rollout should remain blocked until items 1-6 have fresh repository-local proof. Items 7-8 are also required before claiming bounded migration and cross-repository readiness.
