# Audit: OpenClaw deliberation remediation and rollout safety

## Verdict

**NOT SAFE** for live configuration migration or pilot rollout.

The remediation substantially repairs deterministic routing, exact Discord and Slack history, one native text-message attempt, single-message receipts, duplicate attempt detection, and canonical runtime configuration. The repository-local rollout contract is still not closed: pre-transform exclusive ownership is dropped by the channel policy projection, the wire model still groups provider events into 60-second multi-message records, unknown delivery can coexist with a later successful attempt, executable fixtures terminalize an ambiguous timeout, the current build omits the doctor migration artifact, the accepted owner-runtime integration remains 12/23, and scoped extension lint is red.

Live KM deployment, live OpenClaw configuration, Slack allowlists, selected pilot channels, and runtime rollback readiness were not inspected and remain external unknowns. These unknowns are not the reason for the verdict; repository-local blockers are sufficient.

## Scope

- Repository: current `openclaw-fork` checkout only.
- Commit: `90eeb86db1e74fc6048a641a5095cdd4b665d72c`.
- Audit timestamp: `2026-08-22T16:38:38Z`.
- Worktree: heavily dirty; 70 tracked files differ from `HEAD` with 5,774 insertions and 1,495 deletions, plus untracked implementation and evidence files.
- Excluded: production code changes, live configuration, KM state, credentials, deployment, restart, Slack access changes, and pilot execution.
- Historical owner proof was preserved rather than reconstructed. No approved contract-converged KM checkout was available for a fresh owner-runtime run.

## Residual Remediation

1. **Enforce source ownership before channel side effects.** Carry `dispatch: "exclusive"` through `resolveChannelInboundEventPolicy` and the Discord/Slack monitor state, or claim the configured source before ack/typing, auto-thread creation, command/fast-abort execution, and ordinary dispatch. Add loader-backed tests proving one intake and zero ordinary side effects for success, KM failure, disabled, empty, room-event, and Discord auto-thread paths.
2. **Restore one event per deliberation item in the wire model.** Remove the 60-second multi-message burst/record representation from `km-wire-v1.json`, fixtures, runtime parsing, and owner handoff. Keep thread messages available only through history evidence. Prove two same-window provider IDs create two durable records with independent deadlines.
3. **Make unknown delivery permanently fenced.** Define and execute owner recovery from invoked ambiguity to a terminal non-reservable unknown state. Reject any history where `DELIVERY_UNKNOWN` is followed directly by another send; permit a later send only after explicit durable positive proof that the prior attempt was `NOT_SENT`, if the product contract allows that transition. Add a poll-across-lease-expiry composition test.
4. **Align terminal failure semantics and immutable history.** Remove `transport` and `timeout` from caller-submittable definitive `FAILED` completion evidence, replace the timeout fixture with a real authoritative rejection, and compare every historical attempt's pipeline/target envelope with the record's immutable admitted evidence.
5. **Ship and prove the migration artifact.** Ensure `doctor-contract-api.ts` is present in the tracked/built Deliberation surface, then run a real temporary-config `openclaw doctor --fix` discovery/writeback test followed by canonical startup parsing. Keep runtime legacy acceptance absent.
6. **Obtain owner-runtime GREEN.** Select an owner-approved immutable KM revision whose accepted contract, fixtures, target parser, persistence, and recovery semantics match OpenClaw. Rerun the unchanged 23-scenario command and require 23/23 before considering any live configuration change.
7. **Clear related static checks.** Resolve the three scoped Deliberation lint findings and rerun the same scoped lint commands.
